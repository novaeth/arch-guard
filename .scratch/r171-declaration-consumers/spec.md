# 例外 / 建议豁免 0 命中即红

Status: done

## 场景（对应 REQUIREMENTS.md 的 R-171）

- 某次重构后，`exceptions` 里那条例外对应的违规已经消失，但配置没删。报告附录写「未命中（可能可以删掉）」，
  退出码 0 —— AI 不会去读附录，更不会主动删；几轮之后豁免账本里一半是死的。
- `adviceAllow` 同理：它现在只推一条 notice，AI 的目标是让门禁通过，不会处理。

## 背景与问题

本工具面向 AI，只有退出码会改变行为（R-169 / R-170 同一条理由）。
"声明必须有消费者"是仓库既有原则；0 命中说明这条声明已经没在看任何东西，等于隐形的门禁关闭。
过期例外已经 throw，0 命中却只提示 —— 两者是同一类配置腐烂，纪律应该一致。

## 目标

- `exceptions` 0 命中：例外过滤后检查命中数，0 → 抛配置错误（退出码 2），点名 `rule` × `glob` 与 `reason`。
- `adviceAllow` 0 命中：不再推 notice，改为抛配置错误，点名 `signal` × `glob` 与 `reason`。
- 报告里的「未命中（可能可以删掉）」分支移除（0 命中已到不了报告）。
- 文档同步：USAGE §5 / PARADIGM §7 / DESIGN §6.6 / CONTEXT。

## 非目标

- 不改 `exceptions` 的"后置过滤"语义，也不改 `adviceAllow` 的豁免匹配口径。
- 不把 `declaration-no-match`（`structure.*` 的 0 命中自述）升成 error：有些声明是给未来 / 迁移用的，
  升了会误伤；这次只收**例外账本**这一种。

## 验收标准

- 单测：`exceptions` 0 命中 → 退出码 2，报文含「声明必须有消费者」与 rule × glob；
  `adviceAllow` 0 命中 → throw，报文含 signal × glob。
- 有命中的例外 / 豁免照常工作（`$name.test` 的既有断言不改）。
- 示例与狗粮照常通过（`examples/full-fsd` 的那条 `adviceAllow` 是命中的）。
- `pnpm check` 全绿。

## 边界与取舍

- 0 命中在规则跑完后才知道，所以是**运行期抛错**而不是 `loadConfig` 期；与"过期即红"同一落点。
- `--report-only` 也不放过：配置错误与"代码违规"不是一类。
- 这是破坏性配置变更：现存项目里失效的例外会立刻变红，按报文删掉或修对即可。
