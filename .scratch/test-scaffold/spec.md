# 测试脚手架不是产品代码纪律的对象

Status: done

## 场景（对应 REQUIREMENTS.md 的 R-159；写不出这一节的需求先不做）

- **测试辅助文件放在 `__tests__/` 下、但不是 `.test.`**：`src/shared/lib/__tests__/big-helper.ts` 有 200 行
  夹具构造，**现在** S16 会按产品文件量它的行数（阈值 500/页面 500 是给产品代码定的）；
  宿主只能对每个 `__tests__/**` 写一条 S16 例外（多一个包、多一种方言就多一条）。
- **测试夹具要真起子进程 / 真解析 argv 才能验证行为**：`src/shared/lib/__tests__/argv-helper.ts` 里
  `process.argv[index]` 是**被测对象**，**现在** P06 按「手搓 argv 解析」报 error；宿主同样只能写例外，
  或者把这条规则整条关掉。
- **现在拦不拦得住**：H07/H08/H09 已经统一到 `isTestPath`（`__tests__/` 不算生产路径），
  **S16 / P06 没跟上** —— 同一句口径在引擎里有两套实现，规则各写一遍必然再漂一次。

## 背景与问题

"测试文件是脚手架，不是产品代码" 是**引擎级**的口径，不是某条规则的私有判断：
角色的权威来源是配置里的 `test` 角色（层号 ≥ `TEST_LAYER_MIN`），路径判据是 `isTestPath`
（`.test.` / `.spec.` / `__tests__/`）。但体积（S16）与能力指纹（P06）各自漏了这一步，
宿主于是用 `exceptions` 逐类消音 —— 例外是按目录写的，目录里未来的真违规也一起免责。

## 目标

- 规则契约新增 `appliesTo: 'product' | 'all'`（缺省 `'all'` = 行为不变），`createRule` 透传。
- 引擎在收集规则发现项时，对 `appliesTo: 'product'` 的规则统一跳过测试脚手架：
  `role === 'test'` 或 `isTestPath(rel)` 或 `layer >= TEST_LAYER_MIN`。
- S16 与 P06 标 `appliesTo: 'product'`：测试脚手架不再产生发现项；同一条规则在产品代码上的判定不变。
- 口径只有引擎一处：后续规则要"不吃测试脚手架"只写一个字段，不再各写正则。

## 非目标

- **不改**其它规则的判定对象（例如 S15 的孤儿判定、C01 的裸文案）：它们的口径各自有理由，不在本项扩大。
- 不做"测试脚手架完全免检"：测试文件照常进文件集、进依赖图、被需要它的规则判（例如测试目录角色、
  M08 的测试↔源配对）。
- 不为测试文件另设阈值（`viewLines` / `fileLines` 的测试版本）：那会变成第二套刻度。

## 验收标准

- 规则契约：`coreRules` 里 S16 / P06 的 `appliesTo === 'product'`；其它规则缺省不变。
- 夹具：`__fixtures__/rules` 加 60 行 `__tests__/big.test.ts`（阈值 40）→ 不报 S16，产品文件照报；
  `__fixtures__/deps` 加读 `process.argv` 的 `__tests__/argv-helper.ts` → 不报 P06，产品文件照报。
- 单测 `tests/rule-applies-to.test.mjs` 覆盖上述两对；`pnpm check` 全绿。

## 边界与取舍

- **角色优先**：`role === 'test'` 是权威；路径与层号是"拿不到角色"时的兜底（测试在契约扫描域外时常见）。
- **只对声明的规则生效**：不改缺省值是刻意的 —— 一次性让所有规则忽略测试文件会改变十几条规则的覆盖，
  那是另一个决定（要哪条改哪条）。
- 被否方案：在 S16 / P06 内部各加一次 `isTestPath` 判断。否掉的理由：0.11.2 已经有一次"三条规则各留一份
  正则"的漂移（H07/H08/H09 修完才统一）；再加两处就是第三次。
