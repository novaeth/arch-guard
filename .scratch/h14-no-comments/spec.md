# H14 禁止注释（默认关闭）

Status: done

## 场景（对应 REQUIREMENTS.md 的 R-172）

- 团队要求代码只靠命名与类型表达，AI 却爱写"// 导入 x"这类噪声注释；或者反过来，
  团队想保留许可证头、但禁止其余注释。**现在：没有任何规则管注释**（只有 H13 要求生成物带
  `@generated`，方向相反）。

## 背景与问题

注释是不是噪声是**项目口味**，不是通用不变量：有的团队靠注释讲"为什么"，有的团队认为注释会腐烂。
所以这条规则必须**默认关闭**，由宿主显式声明；同时不能静默空转 —— 没声明时报告里要明列停用。

## 目标

- 新增 H14（L2 error）：TS / JS / CSS（含 SCSS / Less）文件里出现任何注释就报，按文件汇总注释数并指向第一条。
- **生成物跳过**（`structure.generated`）：它们必须带 `@generated`（H13），与"禁止注释"天然冲突。
- 测试脚手架不判（`appliesTo: 'product'`）。
- **默认关闭**：`requires: ['structure.noComments']`；宿主写 `params: { noComments: true }` 才启用。
- 确实要保留的注释（许可证头）用 `exceptions` 声明 H14。

## 非目标

- 不判"注释写得好不好"（那是 review）。
- 不判 JSON（没有注释语法）。
- 不默认开启：口味类判断不进默认红线（N-03）。

## 验收标准

- 单测：有注释 → 1 条 finding（汇总数 + 第一条行号）；无注释 / 生成物 / 非 ts → 不报。
- 夹具 `__fixtures__/comments`：`bad.ts` 有注释必报，`good.ts` 无注释不报；`exact`。
- 默认关闭：没写 `params.noComments` 时，报告明列「能力未声明：structure.noComments」，0 finding。
- `pnpm check` 全绿（规则总数 108 → 109，三个示例的启用数不变）。

## 边界与取舍

- 一条注释都不许，会把许可证头也报掉；用 `exceptions` 按文件声明，不发明新的注释分类。
- 生成物整类跳过，而不是逐条豁免 `@generated`。
- 规则数 +1，但默认停用，所以示例的"在跑"数量不变。
